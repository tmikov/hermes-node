Every test of the ImGui JS binding and of `examples/imgui-app/` was shown
able to fail by a recorded mutation (the Mutations table of
`docs/superpowers/plans/progress-imgui-binding.md`). Some properties hold,
by reading or by a check made by hand, that no automated test would notice
losing. They are listed in that file's "Behaviours no test detects", with
how each was checked; in short:

- ImGui's recoverable-error output to stdout is off
  (`io.ConfigErrorRecoveryEnableDebugLog = false` in `setRecoveryFlags()`,
  `addons/imgui/bind/bind_guards.cpp`). Lit's stdout is a file, fully
  buffered, and every windowed process ends in `_exit()`, which discards
  it; checked by hand under a pty (the command is in the progress file).
- An N-API failure never returns silently (`Call::napiOk()`): those
  statuses fail only on engine errors no JavaScript value produces.
- `__test.setDoubleClickTime()` and `__test.setTooltipDelay()` take effect:
  each exists to remove a dependency on frame timing, so the tests pass at
  ImGui's defaults too.
- `Call::write(RefString)` measures with `strnlen` bounded by the capacity
  (the buffer is always terminated), and invalid UTF-8 from ImGui is not
  reachable.
- A `Float32Array` is used in place, not copied (a copy draws the same).
- `listClipper` never steps again after the callback threw: Hermes's
  `napi_call_function` refuses to call with an exception pending, so the
  mutation passes.
- A settings string's size stays inside ImGui's `int` arithmetic only
  because Hermes caps a string at 2^28 UTF-16 units.
- `listClipper` takes ImGui's usage errors after `Begin()` and each
  `Step()`; none is reachable with an `itemHeight` of at least 1.

Reached by no test in the application (Task 9 notes): the Open Folder and
About modals, the View toggles, Dark / Light, the ImGui Demo and Metrics
toggles, File > Quit through the menu (the test calls `app.quit()`), a
symbolic link in the tree, the Log's filter and its follow-the-bottom rule,
and the canvas's drag, speed and pause. (The 5000-entry cap and its "... N
more" row, on that list in Task 9's first notes, are now tested: BIG in
`test/ui-imgui-app.js`.)

Done when each item has a test that fails without it, or is recorded as
accepted untested with the reason (most are untestable by construction:
the stdout buffer, engine-only N-API failures, timing hooks whose purpose is
to remove the dependency the test would need).
