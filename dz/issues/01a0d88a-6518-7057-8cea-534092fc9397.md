Closing the window ends `sapp_run()` on Linux, so `uiRunPlatformLoop()`
returns and `UiHost::run()` calls `uv_thread_join()`. The JS thread is by
then inside `UvEventLoop::close()`'s `uv_run(UV_RUN_DEFAULT)`, holding the
referenced libuv handle that `createWindow` took and that nothing ever
closes. Both threads block forever: no message, no exit code, and no
terminal restore.

Each half is documented on its own -- the keep-alive comment says a script
that simply returns waits forever, and the join comment says a program
normally ends through `process.exit()`. The composition is named nowhere,
and closing the window is the one way a user ends a windowed program
*other* than `process.exit()`.

Both window tests call `process.exit(0)`, so nothing in the suite goes near
it. That is why it survived six task reviews and was only found by looking
at the whole slice at once.

Task 15 owns the fix: it introduces CLOSING and the pre-cleanup lifecycle
hook that closes the UI handle so `UvEventLoop::close()` can finish. Filed
now rather than left to that task's brief because "run the demo, then close
the window" is the first thing anyone will do with this slice, and the
symptom gives them nothing to go on.

    Interim behaviour as of Task 11b (Ruling 54): the close button no longer closes the window. sokol_app's QUIT_REQUESTED is cancelled with sapp_cancel_quit() in uiHandlePlatformEvent and forwarded to JavaScript as a 'close' event on the window object (and to native listeners as HNUI_EVENT_CLOSE_REQUESTED), so sapp_run() does not return and the hang described above is no longer reached by clicking close. A script ends itself with process.exit() from its 'close' listener; one that has no listener now gets a window that cannot be closed from its title bar, which is observable rather than a silent hang but is not the intended behaviour. The default action for an uncancelled close -- CLOSING, the pre-cleanup lifecycle hook, releasing the referenced handle so UvEventLoop::close() can finish -- is still Task 15's, and this issue stays open for it. Pinned by test/ui-events.js (CLOSE): close is emitted and the process keeps running.
