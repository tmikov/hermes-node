Node exposes `performance` as a global (and `require('perf_hooks')`), and
hermes-node has neither:

    hermes-node -e 'typeof performance'          # undefined
    hermes-node -e 'require("perf_hooks")'       # Cannot find module
    node        -e 'typeof performance'          # object

Found while checking how far Ink gets (see
`docs/notes/2026-08-24-ink-findings.md`). Ink 6.4 compiles and starts, then
dies at the first render with `ReferenceError: Property 'performance'
doesn't exist` from its own `onRender` timing. A three-line stub
(`performance.now = () => Date.now()`) was enough to get a correct render,
so nothing deeper is involved -- the global is simply absent.

`performance.now()` is the part anything is likely to want; the rest of the
User Timing API (`mark`, `measure`, `timeOrigin`, the entry buffer) is a
larger surface and probably not worth it up front. Node's own
`perf_hooks.performance` is the reference.

Worth having because it is the kind of gap that stops a library at its first
frame rather than at some feature nobody uses, and because a stub is cheap.
