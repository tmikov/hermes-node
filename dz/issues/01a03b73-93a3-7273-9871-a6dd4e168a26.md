`--build-exe` needs clang specifically, not merely "a C++ driver", and offers
no way to say otherwise.

The assemble step passes `-Qunused-arguments`
(`lib/build-exe/build_exe.cpp:209`), which is a clang spelling. Measured:

    $ g++ -Qunused-arguments -c t.s -o t.o
    g++: error: unrecognized command-line option '-Qunused-arguments'
    exit 1

So hand-editing `cc:` in the manifest to `g++` fails at the first step, before
the forwarded `driverflag:` list -- also clang-shaped, being whatever CMake
handed clang -- gets a chance to fail too. There is no `--cc` override flag, so
the only way to change the compiler is to edit the generated manifest, and that
does not work.

The accepted design trade is a *linker* on the build machine, which Static
Hermes needs anyway. That is not what this asks for. It asks for one particular
C++ driver, and clang is not installed by default on most Linux distributions.

Two directions, not exclusive:

- Stop needing a compiler for the assemble step at all (filed separately as the
  direct-object-emission task). That removes `-Qunused-arguments` along with the
  step it belongs to.
- Add a `--cc=<path>` override so a user can point at whatever they have, and
  drop or conditionalize the clang-only flags on the driver actually in use.

Related: the manifest's absolute `cc:` path is filed separately -- fixing that
one does not fix this one, since a found-on-PATH `g++` still fails here.
