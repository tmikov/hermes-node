Two configurations the Metal backend (Task 16) has guards for. Display
sleep has never been run. A Release build was built and its window tests
run once on 2026-11-21 (below); the whole suite has not been run under
Release.

**Display sleep.** Sokol marks its swapchain invalid while its obscured
timer runs, which starts on an occlusion change; the backend then submits
nothing and sends no frame tick (`present: swapchain invalid; nothing
submitted`). The only cause a test produces is miniaturizing
(`test/ui-metal-occlusion.js`). A display going to sleep while a window
is open was not tried in Task 16d or 16e: nobody had agreed to
`pmset displaysleepnow` at the machine. Unknown, therefore: whether the
occlusion change arrives before the first frame that gets a nil drawable,
and what the one-second `nextDrawable` timeout looks like to a program.
What was measured nearby: with the swapchain-invalid check and our nil
guard both removed, a miniaturized window's frames did not crash, because
Sokol's Metal `begin_pass` skips a nil drawable itself; and with the
session locked and the display asleep from the start, a `sokol_app`
program gets no frame at all.

**A Release build with asserts off.** Every Mac run up to Task 16e was
an ASAN Debug build. Two guards exist specifically because a Sokol assert is compiled
out in Release: `acquireFrameSwapchain` checks for a nil drawable
(`_sapp_mtl_swapchain_next` only asserts it), and
`createGenerationSurfaces` refuses when fewer than 256 id-pool slots are
free (Sokol asserts on an empty pool). CI's macOS `release` job does not set
`HERMES_NODE_ENABLE_UI`, so it does not build this code.

*Done on the Mac, 2026-11-21 (Task 16f's verification):* a Release build
with `HERMES_NODE_ENABLE_UI=ON` was configured and built in a build
directory of its own -- the ASAN UI configuration's options except
`CMAKE_BUILD_TYPE=Release` and `HERMES_ENABLE_ADDRESS_SANITIZER=OFF` --
with no warning in our sources. The window tests (`test/ui-*.js`, 39
files) were run there once: 34 passed, 5 unsupported, 0 failed. The five
are the four UI tests unsupported in the ASAN build too
(`ui-clipboard.js`, `ui-real-events-demo.js`, `ui-display-busy.js`,
`ui-sokol-validation-ci.js`) plus `ui-sokol-validation.js`, because a
Release build compiles Sokol's validation layer out.

*Not done:* the whole suite (`check-hermes-node`) was not run under
Release, only the window tests, and only once. That run does not say
whether any test reached either guard: nothing in it forces a nil
drawable past the swapchain-invalid check or an id pool below 256 free
slots.

To close this: one run of a window program across
`pmset displaysleepnow` with `HERMES_NODE_DEBUG_NATIVE=UI`, recording the
trace; and, on a Mac, one pass of `check-hermes-node` in a Release build
with `HERMES_NODE_ENABLE_UI=ON`.
