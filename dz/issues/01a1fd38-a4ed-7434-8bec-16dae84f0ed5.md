The GL backend of the UI compositor (`lib/compositor-gpu/gl_backend.cpp`,
`gl_present.cpp`) has been run on two GL implementations and no others.

What was measured:

- **Mesa llvmpipe under Xvfb.** This is what the suite's window tests run
  on, on the development machine and in Linux CI. At the close of Slice D
  (2026-11-21) `check-hermes-node` with `HERMES_NODE_ENABLE_UI=ON` was 456
  unit tests passed and JS 234 passed, 10 unsupported, 0 failed.
- **AMD radeonsi (Radeon 780M, Mesa 25.2.8), 2026-09-21**, with the raw-GL
  probe `test/fixtures/hnui-spike/glx_share.c`, not with the suite: a
  shared context goes current on a second thread with no drawable, and
  sync objects are visible across the share group (the spec records
  94,603 timeout-0 polls over 14.57 ms before one signalled). That ran in
  an XWayland session. See
  `docs/notes/2026-09-21-linux-hardware-spike-results.md`.

What was not:

- **NVIDIA's proprietary driver.** The spec
  (`docs/superpowers/specs/2026-09-18-ui-compositor-design.md`) says it is
  "untested and is the most likely of any to differ", on both questions
  above: the surfaceless context route and cross-context sync objects.
  The startup probe exists so that a driver that differs falls back
  instead of failing; the suite reaches the other route and the other
  completion mode by forcing them (`HERMES_NODE_UI_GL_ROUTE`,
  `HERMES_NODE_UI_GL_COMPLETION`), on llvmpipe.
- **Native Xorg**, as opposed to Xvfb and XWayland.
- **Intel GL.**
- The whole suite on any hardware GL driver, AMD included: the AMD
  measurement was the probe only.

To close this, for each of the three: on a machine that has it, build
with `HERMES_NODE_ENABLE_UI=ON` and run
`cmake --build <build dir> --target check-hermes-node`, on a native X
server with `HERMES_NODE_UI_EXPECT_DISPLAY=1` in the environment so that
a missing display is red, not UNSUPPORTED. Note that `%with-display`
starts its own Xvfb on Linux, so the window tests as written draw with
whatever GL that Xvfb gives them; reaching the hardware driver needs the
wrapper pointed at the real server, which nothing provides today. Record
the totals, the context route and completion mode the trace reports
(`HERMES_NODE_DEBUG_NATIVE=UI`), and any `[sapp:` or `[sokol-` line.
