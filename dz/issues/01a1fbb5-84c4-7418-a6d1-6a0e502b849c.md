Sokol creates no main menu on macOS, and `hermes-node-ui` adds none. Cmd-Q
is a key equivalent of the application menu's Quit item, so with no menu
there is nothing for it to invoke: pressing it in a `hermes-node-ui`
program is expected to do nothing. This is read from Sokol's source and
from how AppKit routes key equivalents; **it was not tried at the
keyboard**.

The rest of the path exists. `HnuiApplication` (`tools/hermes-node-ui/
mac_app.mm`) overrides `terminate:`, which is the action a Quit menu item
sends, and turns it into the cancelable `close` event
(`test/ui-terminate.js`). So a minimal menu whose Quit item targets
`terminate:` would be enough for Cmd-Q to behave like the window's close
button.

Not done in Task 16 because a main menu is a feature with its own
questions (the application name shown, whether a program can add items,
what the other standard items do). Testing it is a second question: the
suite runs with the application refusing activation
(`HERMES_NODE_UI_TEST_NO_ACTIVATE`), and whether a menu key equivalent can
be exercised in that state is not known.
