Two differences from Node in how an unhandled promise rejection is
reported, found while fixing `process.emit()`'s return value for Task 9 of
the ImGui binding and recorded, not asserted, in the header of
`test/test-process-emit-return.js`. Related to 01a1d5c0-d385 (a throw in a
`.then()` callback does not reach an `uncaughtException` listener), which
is about routing; these two are about the reported value and the timing.

Measured 2026-11-28, node v24.13.1 against `cmake-build-asan/bin/hermes-node`:

1. **The reported Error is wrapped.** `Promise.reject(new Error('boom'));`
   alone:
   - node: prints the `Error: boom` itself with its stack (its first frame the
     script's own line 1), exit 1.
   - hermes-node: prints `UnhandledPromiseRejection: This error originated
     either by throwing inside of an async function without a catch block,
     or by rejecting a promise which was not handled with .catch(). The
     promise rejected with the reason "Error: boom".`, with a stack through
     `throwUnhandledRejectionsMode` and `processPromiseRejections`, exit 1.

   The cause: the vendored `isErrorLike()`
   (`libjs-node/internal/process/promises.js`) requires an own `stack`
   property, and Hermes defines `stack` as an accessor on
   `Error.prototype`: `Object.getOwnPropertyDescriptor(new Error('x'),
   'stack') !== undefined` is `true` under node and `false` here, while
   `typeof e.stack` is `'string'` in both. So the original Error, its
   message and its throw-site stack are not what the user sees.

2. **Rejections are processed late.**
   `process.once('unhandledRejection', (r) => console.log('LISTENER ' +
   r.message)); Promise.reject(new Error('first')); setTimeout(() =>
   console.log('TIMER 200ms'), 200);`:
   - node: `LISTENER first`, then `TIMER 200ms`, exit 0.
   - hermes-node: `TIMER 200ms`, then `LISTENER first`, exit 0.

   Node runs the listener before the timer; here it ran only after a
   200 ms timer had fired. 01a1d5c0-d385 notes that rejections are detected on a timer
   (`lib/bindings/node_task_queue.cpp`, "Promise rejection tracking").

Done when both scripts print what node prints (an `isErrorLike()` that
accepts Hermes's Error, for instance by testing `stack` through `in` or
by type, and rejection processing in the same turn), with a test that
pins each against node's output; `test/test-process-emit-return.js`'s
rejection run can then gain its "still alive" timer and assert the
unwrapped Error.
