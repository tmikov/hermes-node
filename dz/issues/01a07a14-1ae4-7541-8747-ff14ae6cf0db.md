Minor test-quality items from the final whole-branch review of the Wasm
compile cache (2026-09-07). Neither is a bug; both are tests that pass
whether or not the thing they name is working.

**`WasmCache_TooSmallStructIsRejected`**
(`hermes/unittests/napi/NapiWasmCacheTest.cpp`) was written for the fix in
`683eb9bb6`, which moved `hermes_set_wasm_cache`'s `struct_size` check ahead
of the dereferences it guards. But the test sets a small `struct_size` on a
*fully sized* object, so no out-of-bounds read occurs either way and the
test passes with or without the fix. Catching the original defect needs a
genuinely truncated allocation.

**The accepting half of the same check is untested.** `683eb9bb6` also
changed `!=` to `>=`, so a caller from a newer header with a *larger*
`struct_size` is accepted and only the known fields are read. Nothing
exercises that path.

Also noted, in the same file: `FakeCache::lastConfig` is recorded and never
asserted. The end-to-end coverage for `codegen_config` now exists on the
hermes-node side (`test/test-wasm-cache.js` runs a file plain and with
`--vm=-test262` and requires four entries rather than two), so this is
redundancy rather than a gap -- but the unused member should either be
asserted or removed.
