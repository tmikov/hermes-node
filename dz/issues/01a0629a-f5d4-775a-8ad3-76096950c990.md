`--build-bundle --verbose` narrates each recorded VM option as it goes
(`BuildReporter::vmOptionRecorded`) and prints the lock state unconditionally
(`BuildReporter::vmOptionsLock`), but its end-of-build summary
(`BuildReporter::summary`, `lib/bundle/bundle_build.cpp`) has no `vm-opts:`
count line, where it does tally `preloads:` and `natives:`.

Nothing is unobservable as a result -- the per-option lines above already say
everything -- so this is narration completeness rather than a defect. The
whole-branch review triaged it explicitly as "leave": the summary's job is the
finished container's shape, and it does not duplicate the natives audit path
(`--verify-natives`) either.

Worth doing only when someone is next in that function. If the counts are ever
made uniform, the row belongs beside the existing two, and the format is
already established by them.
