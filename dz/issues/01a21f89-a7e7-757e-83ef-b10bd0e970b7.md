`hermes-node-ui` honours no Hermes VM option from any of the three sources
`hermes-node` reads (CLAUDE.md, "Hermes VM Options"): `--vm=` is refused,
and `HERMES_NODE_VM_OPTIONS` and a container's baked options are ignored
silently. Found when an ImGui binding test needed
`-Xhermes-internal-test-methods` (for `HermesInternal.detachArrayBuffer`);
the addon grew a test hook, `__test.detachArrayBuffer()`, instead.

Measured 2026-11-28, `cmake-build-asan`, with a script printing whether
`new Function('return 1')()` throws (`-enable-eval=false`, the flag
CLAUDE.md recommends for observing a VM option) and with
`typeof HermesInternal.detachArrayBuffer` (`-Xhermes-internal-test-methods`):

- `hermes-node --vm=-enable-eval=false s.js` and
  `HERMES_NODE_VM_OPTIONS=-enable-eval=false hermes-node s.js`: eval off.
  `HERMES_NODE_VM_OPTIONS=-Xhermes-internal-test-methods hermes-node`:
  `function`.
- `hermes-node-ui --vm=-enable-eval=false s.js`:
  `Error: unknown option '--vm=-enable-eval=false'`, exit 1. Deliberate:
  `tools/hermes-node-ui/main.cpp`'s parser refuses by name every
  `hermes-node` flag it does not implement, `--vm=` among them.
- `HERMES_NODE_VM_OPTIONS=-enable-eval=false hermes-node-ui s.js`: eval
  **on**, exit 0; with `-Xhermes-internal-test-methods`, `undefined`. The
  variable is read by `tools/hermes-node/hermes-node.cpp` and
  `bundle_main.cpp`, not by `runHermesNode()`, so this binary never sees
  it. That is the silent no-op on a VM setting the VM-options work
  refuses everywhere else.
- A container built with `hermes-node --build-bundle=app.hbb
  --vm=-enable-eval=false` (locked, the default): `hermes-node
  --bundle=app.hbb` runs with eval off; `hermes-node-ui --bundle=app.hbb`
  runs with eval **on**. A locked container's baked options are the
  artifact's own configuration (the honoured set includes `-enable-eval`,
  which CLAUDE.md calls out as not a tuning knob), and this binary drops
  them without a word.

Done when `hermes-node-ui` applies a container's baked options and
`HERMES_NODE_VM_OPTIONS` with `hermes-node`'s precedence and lock rule
(sharing its code, not a copy), or refuses both by name before starting a
runtime; `--vm=` is supported or stays refused by name; and a test in the
`ui` suite pins each of the three (a script and a container, each run
under `hermes-node-ui`, observing `-enable-eval=false`).
