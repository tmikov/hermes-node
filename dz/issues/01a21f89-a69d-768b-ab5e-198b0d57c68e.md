The JS binding of Dear ImGui (`addons/imgui/bind/`) checks every argument
and guards the closers ImGui would assert on (`bind/bind_guards.cpp`), but
some plain assertions, and some unchecked reliance on state, remain
reachable from JavaScript. Each is an abort in a Debug build and undefined
behaviour in a Release build, as for a C++ program calling ImGui the same
way. The full list, with ImGui's source lines and what was measured, is the
"Not covered (for the tracker)" section of
`docs/superpowers/plans/2026-11-27-imgui-binding-surface.md`; in short:

1. `beginTable` again in one frame with the same ID and another column
   count (a lookup in `g.Tables` by the ID ImGui would compute).
2. `beginMainMenuBar()` called again before `endMainMenuBar()` (the
   condition is on a window that is not current at the call; the same
   mistake with `beginMenuBar()` is guarded).
3. A string ID whose hash is zero (`beginChild`, `beginListBox`,
   `beginTabBar`).
3b. Closing a scope ImGui opened internally with another pair's closer:
   `beginMenuBar(); endGroup();`, and `begin('w');
   treeNodeEx('n', TreeNodeFlags_DefaultOpen); popID(); end();` (measured
   to abort in the window recovery's own `TreePop()`). Every closer that
   ends a window runs that recovery and inherits these sequences. A guard
   checks that something of the closer's kind is open, not who opened it.
3c. Re-entering a window that holds a table: `beginChild` with an ended
   scrolling table's own `strId` (abort), or a window holding an open
   table re-entered while a later table is open (abort, or with a third
   table a frame-end recovery that loops until the time limit).
3d. Table column layouts ImGui cannot build that depend on its own layout
   computation: every column disabled through visibility or settings, and
   64 or more sorted columns.
3e. A tree node that keeps stack data left open in a scrolling table's cell
   (abort inside `endTable()`).
3f. Positions and sizes that reach 2^31 only as a sum (cursor, window
   position, indent), which ImGui converts to `int`; and `colorButton`'s
   unclipped alpha checkerboard, about `(size.x / size.y) * 9` rectangles.
   Arguments converted as they are, are bounded.
3g. A settings string ImGui cannot apply: a self-parented dock node (the
   load never returns), a window docked into a missing node (abort), a
   chain of 300 nodes (the next save aborts). `addons/imgui/README.md`
   says to load only text `saveIniSettingsToMemory()` produced.
3h. A dock splitter dragged while `StyleVar_DockingSeparatorSize` is pushed
   above its node's size (found by reading, not measured): the locked
   child's size is -1 and a plain assertion follows.
3i. A `dragInt` driven from the keyboard (reachable only by clicking it in
   the frame Tab moved to it): the accumulator is bounded by the frame's
   length, and reaches 2^30 at the speed bound after a frame of about
   2000 s with an arrow key held.
3k. A value typed into the colour picker's own editors: written to the
   array or saved as the hue and read back by the next editor and the
   picker inside the same ImGui call, where the binding cannot intervene.
3j. Text typed into a number field: `sscanf` into the value's type, which
   the C standard leaves undefined for a number that does not fit.

Items 4 and 5 of that section (guards as weak as ImGui's own checks, two
`ImDrawFlags` values that pass the bit test) are recorded there and are not
crashes.

Part C (the generated binding) should decide 3b, since preventing it needs
the binding to track which scopes its caller opened; the draw list's clip
rectangle issue needs the same tracking.

Done when each item is either prevented (a guard or argument check with a
refusal case in `test/ui-imgui-bind-errors.js` or the group's test, and a
recorded mutation), or explicitly accepted as the caller's responsibility
and said so in `addons/imgui/README.md`; the surface table's section then
lists only the accepted ones.
