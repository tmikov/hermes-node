Split out of dz 01a11df9-3c69 (StaticHUnitTest failures), where it was noted
as a separate question.

With `HERMESVM_INTERNAL_JAVASCRIPT_NATIVE` ON (this tree forces it, top-level
`CMakeLists.txt:59`), `cmake-build-asan/hermes/unittests/VMRuntime/HermesVMRuntimeTests`
ends with an ASAN leak report: 43,728 bytes allocated by
`sh_export_internal_unit` (the generated creator `calloc`s its `UnitData`)
via `Runtime::runInternalJavaScript` -> `_sh_unit_init`. Every runtime the
test binary creates registers the internal unit, and its data is apparently
not freed when the runtime is destroyed.

hermes-node itself never reports it: both of its exit paths call `_exit()`
deliberately (see CLAUDE.md, Bootstrap Sequence), so no runtime is destroyed.
An embedder that creates and destroys runtimes repeatedly would leak this
much per runtime.

Not verified: whether a non-internal native unit registered with
`_sh_unit_init` leaks the same way, i.e. whether this is general SH unit
ownership at runtime teardown or specific to the internal unit.
