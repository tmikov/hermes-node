In Node a throw inside a `.then()` callback is an unhandled rejection, and
under the default `--unhandled-rejections=throw` mode it is raised as an
uncaught exception: an `uncaughtException` listener receives it and the
program carries on. In hermes-node the listener never runs and the process
exits 1.

Reproduction (`repro.js`):

    process.on('uncaughtException', (e) => console.log('listener: ' + e.message));
    Promise.resolve().then(() => { throw new Error('boom'); });

Measured 2026-11-13:

- node v24.13.1: prints `listener: boom`, exit status 0.
- hermes-node (cmake-build-asan, 2026-11-13): prints
  `UnhandledPromiseRejection: This error originated either by throwing
  inside of an async function without a catch block, or by rejecting a
  promise which was not handled with .catch(). The promise rejected with
  the reason "Error: boom".` with a stack through
  `throwUnhandledRejectionsMode (internal/process/promises:78:10)` and
  `processPromiseRejections`, exit status 1.

Rejections are detected on a timer (lib/bindings/node_task_queue.cpp,
"Promise rejection tracking"), and the error `throwUnhandledRejectionsMode`
raises is not routed to the listener the way Node's
`triggerUncaughtException(err, true /* fromPromise */)` routes it. Not UI
code: found while writing test/ui-raf.js, whose HANDLED case throws from
`nextTick` rather than from a promise callback for exactly this reason.
