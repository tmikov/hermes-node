The ImGui addon pastes through ImGui's own path: the shortcut chord
(Ctrl+V, Cmd+V on macOS) reaches ImGui as key events, and ImGui calls
`Platform_GetClipboardTextFn`, which is `hnui_read_clipboard_sync`. The
listener deliberately ignores `HNUI_EVENT_PASTE`
(`addons/imgui/imgui_platform.cpp`).

Nothing tests that it keeps ignoring it. `test/ui-imgui-clipboard.js`
injects its chords with `ui.__injectEvent`, which enters below Sokol, and
Sokol produces `SAPP_EVENTTYPE_CLIPBOARD_PASTED` only from a real key
event (`_sapp_x11_key_event` in sokol_app.h; on macOS on Cmd+V key-down).
So no `HNUI_EVENT_PASTE` ever arrives in that test. Mutation (e) of Task 8
(insert the event's text into the field as well) left the test green:
`PASTE text=hellohello`, the text twice and not three times. See
`docs/superpowers/plans/progress-imgui-addon.md`, Mutations, Task 8.

Why no existing tool can send one:

- The X11 window driver (`test/fixtures/hnui-demo/x11_window_driver.c`)
  has `key <keysym>`, a KeyPress and KeyRelease with no modifier state, so
  it cannot send Ctrl+V.
- Injecting `CLIPBOARD_PASTED` directly (`__injectEvent` knows the type)
  would make the event arrive, but alone. It would not reproduce what a
  real key does, which is the point.

What a real Ctrl+V does: Sokol sends KEY_DOWN for V with the CTRL
modifier and then CLIPBOARD_PASTED. The host turns the second into
`HNUI_EVENT_PASTE` carrying text it read itself (`realPlatformSource()`,
`tools/hermes-node-ui/ui_platform.cpp`). So the host performs two
clipboard reads for one keystroke: that one, and the addon's
`hnui_read_clipboard_sync` when ImGui handles the chord.

A test would need a driver command that sends a key with a modifier
(for example `key ctrl+v`, setting the KeyPress state mask, and an
equivalent `cmd-key` path on macOS, where `__driveWindow` already has
`cmd-key <c>`). It would then assert, after copying `hello` and pasting
once with a real Ctrl+V, that the field holds `hellohello` exactly, and
that stderr has one `imgui: clipboard get: ok, 5 bytes` line for that
paste. The host's `paste:` and `clipboard read` lines should show the
second read without it reaching the field.
